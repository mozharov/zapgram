ZapGram превращает Telegram в приложение для Lightning-платежей: мгновенные tips в группах, инвойсы с QR-кодами, переводы между пользователями со скоростью сообщения и платный доступ к закрытым сообществам.

## Возможности

### Lightning-кошелёк

Каждый пользователь получает Lightning-кошелёк в момент первого открытия бота.

- Баланс в сатоши в реальном времени
- **Получить** — создать инвойс (сумма + опциональный memo), поделиться QR / строкой BOLT11
- **Отправить** — оплатить любой Lightning-инвойс или перевести саты Telegram-пользователю `@username`
- Уведомления о входящих платежах и tips

Внутренние переводы между пользователями ZapGram проходят мгновенно и без сетевых комиссий — деньги двигаются как личное сообщение.

### Внешний кошелёк через NWC

Предпочитаете self-custody? Подключите **любой** Lightning-кошелёк с поддержкой [Nostr Wallet Connect](https://nwc.dev/) — например [Alby](https://getalby.com/invited-by/mozharov) или [Coinos](https://coinos.io).

- Привязка по URL вида `nostr+walletconnect://…`
- На экране кошелька видны **оба** баланса (ZapGram + NWC)
- Выбор, с какого кошелька уходят tips в группах
- Оплата подписок с NWC, если хватает баланса
- Отключение в любой момент

Внешний кошелёк остаётся под вашим контролем; ZapGram действует только в рамках выданных прав.

### Tips в группах и каналах

Добавьте бота в чат и отправляйте tips командой `/tip`:

| Команда | Что делает |
|---|---|
| `/tip` | 21 сат владельцу группы (или создателю канала — на посте) |
| `/tip 100` | Своя сумма владельцу |
| Ответ + `/tip` | Tip автору сообщения |
| Ответ + `/tip 1000` | Tip автору с указанной суммой |
| `/tip @user` | Tip конкретному пользователю (по умолчанию 21 сат) |
| `/tip 50 @user` | Tip пользователю с указанной суммой |

Сделайте бота админом (достаточно права удалять сообщения) — tips владельцу работают аккуратно, служебные сообщения не засоряют чат. В каналах tips в ответ на посты уходят создателю канала.

### Поддержка проекта (добровольные донаты)

ZapGram бесплатен. При желании можно поддержать автора бота:

- **Добровольный % сверху платежей** — у новых аккаунтов по умолчанию **5% только на tips**. Процент, область (**только tips** / **все платежи**) и отключение — на экране поддержки в главном меню.
- **Авто-% не блокирует ваш платёж** — сначала проходит tip или оплата счёта; донат автору — best-effort. Успех без уведомления (итоги на `/donate`); при ошибке — только личное сообщение.
- **Хаб `/donate`** — ваша статистика, **общие суммы** (за всё время и за 30 дней), разовые суммы (**21 · 100 · 1 000 · 10 000 · 100 000** или своя) и **ежемесячный** автодонат в боте (раз в 30 дней; при включении — первый платёж сразу).
- **Вне бота** — Lightning-адрес `zapgram@getalby.com`.

Это отдельно от небольшой **комиссии платформы** на Lightning-оплате платных чатов (`SUBSCRIPTION_FEE_PERCENT`).

### Инвойсы: платить и принимать оплату

- **Создать** — сумма в сатах, опциональный memo → фото с QR и копируемый инвойс
- **Оплатить** — вставить или переслать `lnbc…` → проверить сумму, memo, комиссию, срок → подтвердить
- Для чужих инвойсов показывается fee reserve Lightning; уже оплаченные и просроченные обрабатываются безопасно
- Входящие платежи приходят уведомлением и обновляют баланс

### Платный доступ к закрытым чатам

Превратите закрытую группу или канал в сообщество с доступом за **саты** — **Lightning и/или on-chain Bitcoin**.

**Для владельцев**

1. Добавьте `@zap_gram_bot` с правами **приглашать пользователей** и **банить**
2. Откройте **Чаты** в главном меню → включите платный доступ
3. Задайте цену (саты), тип оплаты (**разовый** постоянный доступ или **ежемесячный**), при желании — кастомное сообщение при вступлении (RU + EN)
4. Опционально: **включить on-chain оплату** и вставить account-level **zpub / xpub** (receive-аккаунт). Участники смогут платить on-chain; средства идут на адреса из вашего ключа. Комиссия платформы за Lightning **не** берётся с on-chain рейла.

**Для участников**

1. Подайте заявку на вступление
2. Получите Lightning-инвойс (и кнопку быстрой оплаты, если хватает баланса ZapGram или NWC) и при включённом on-chain — кнопку **Оплатить on-chain**
3. Оплатите любой из рельсов → доступ (on-chain обычно после появления транзакции в сети)

**Подписки**

- Ежемесячное продление списывается автоматически: сначала кошелёк ZapGram, при нехватке — NWC (если подключён)
- Управление автопродлением и статусом — через **Мои подписки** в главном меню
- Ручные инвойсы на продление, если автопродление выключено или оба кошелька не смогли оплатить
- Lightning-вход: владелец получает выплату автоматически (за вычетом небольшой комиссии); дубликаты возвращаются безопасно
- On-chain-вход: саты сразу на кошелёк владельца (xpub); без Lightning fee split

## Архитектура (для разработчиков)

Слои + вертикальные слайсы по фичам. Подробности: **[docs/architecture.md](./docs/architecture.md)**.

```
core → infra → modules → telegram / http / jobs
                ↑
            bootstrap (composition root)
```

Точка входа: `src/main.ts` → `createContainer()` → `createApp()` → старт / graceful shutdown.

### Стек

Bun, TypeScript, grammY, Elysia, Drizzle (SQLite), LNbits, Nostr Wallet Connect, pino, Biome.

**Lightning backend:** [Alby](https://getalby.com/invited-by/mozharov)

### Локальная разработка

```bash
# установка
bun install

# typecheck + lint + тесты
bun run ci

# локальный бот (нужен .env; HOST — публичный HTTPS URL)
bun run start:dev
```

**Запросы фич:** пользователи отправляют их из главного меню. Задай `ADMIN_TELEGRAM_IDS` (Telegram user id через запятую) — новые запросы придут в личку. Опциональные сатоши идут теми же rails, что и `/donate`. В PostHog событие `feature_requested`. Без admin id запросы всё равно пишутся в аналитику.

### On-chain оплата (self-host / ops)

Нужны расширения LNbits **Watch Only** + **SatsPay** на том же инстансе, что и `LNBITS_URL`.

| Настройка | Заметки |
|---|---|
| SatsPay `webhook_method` | **POST** (default GET ломает ZapGram) |
| Сеть SatsPay / Watch Only | Совпадает с `LNBITS_ONCHAIN_NETWORK` (`Mainnet` или `Testnet`) |
| Mempool URL | Mainnet: `https://mempool.space` · Testnet: `https://mempool.space/testnet` |
| `HOST` | Публичный HTTPS origin бота (SatsPay шлёт `${HOST}/satspay/webhook/${BOT_WEBHOOK_SECRET}`) |
| `LNBITS_ADMIN_KEY` | Admin key кошелька бота (WO-кошельки создаются под этим user) |

В compose: `LNBITS_ONCHAIN_NETWORK` (по умолчанию `Mainnet`). Smoke: zpub в меню «Чаты» → join → Pay on-chain → оплата ≥ price → grant.

**Персистентность:** compose задаёт `LNBITS_EXTENSIONS_PATH=/app/data/extensions`, поэтому код установленных расширений LNbits лежит на volume `lnbits-data` (`/app/data/extensions/extensions/<id>`) рядом с БД и переживает пересоздание контейнера. Без этого LNbits 1.x ставит расширения в `/app/lnbits/extensions` внутри контейнера: после редеплоя в БД они числятся установленными, а файлов нет — отсюда `Extension 'satspay' disabled` и 500 при включении. При переходе существующего инстанса на эту настройку один раз переустанови Watch Only и SatsPay (Admin → Extensions); их данные в БД сохраняются.

### Пост-деплой проверка 1.7.0

Compose собирает `lnbits/lnbits:v1.7.0` (тег без digest: у amd64 и arm64 разные манифесты). Том `lnbits-data` остаётся прежним. Его пересоздание открывает мастер `first_install`.

`LNBITS_AUTOUPDATE_EXTENSIONS_ON_STARTUP` задан как `true` (значение по умолчанию в 1.7.0). Это редактируемая настройка: env действует, пока в БД настроек нет сохранённого значения. При старте LNbits обновляет каждое установленное расширение на месте до последней совместимой стабильной версии из того же репозитория-источника и прогоняет миграции расширения. Файлы `ext_*.sqlite3` на томе остаются.

На 1.7.0 нужны **SatsPay 1.2.0** и **Watch Only 1.2.1**. Стоявшие 1.0.2 и 1.1.0 задают исключающий `max_lnbits_version: 1.7.0` и не загрузятся. В теге satspay v1.2.0 файл `config.json` всё ещё содержит `"version": "1.1.0"` при `min_lnbits_version: 1.7.0`. Ориентир — тег релиза и `min_lnbits_version`; строка `version` в `config.json` может отставать.

Ручной fallback, если манифест не скачался и в логе остались 1.0.2 / 1.1.0, расширения disabled, или `GET /satspay/api/v1` отвечает 404:

1. Admin → Extensions.
2. **Update** поверх установленного SatsPay и Watch Only.
3. Uninstall не нажимать. Данные зарядов и watch-only кошельков лежат в `ext_satspay.sqlite3` и `ext_watchonly.sqlite3` на томе.

После старта:

1. В логе версия **1.7.0**, миграции ядра до `m057` без ошибки, `planned restart in 96h`, нет редиректа на `/first_install` и нет `Settings DB empty`.
2. `GET /api/v1/health` → 200.
3. SatsPay 1.2.0 (или тег v1.2.0; см. оговорку про `config.json`) и Watch Only 1.2.1 включены. `GET /satspay/api/v1` → 200. WebSocket SatsPay снова подключён к mempool.space.
4. В логе NWC подключён. `GET /api/v1/status` с админ-ключом показывает funding source NWC. Нулевой баланс бэкенда — ожидаемое состояние, пока нет канала.
5. `GET /users/api/v1/user` с Bearer отвечает как раньше. Тестовый входящий инвойс и lookup по hash. При нулевом балансе исходящий Lightning показывает, что ошибка про средства. On-chain: probe SatsPay и тестовый заряд на существующий watch-only кошелёк (затем удалить заряд).
6. После первого входящего платежа вебхук доходит до бота. Если его отвергает SSRF, смотреть `HOST`, `lnbits_baseurl` и `lnbits_outbound_host_ips`. Сверка pending-инвойсов по cron остаётся запасным путём.
7. Аккаунты с 06.11.2026 совпадают с логами бота о создании кошельков. Посторонние аккаунты останавливают выкладку.
8. Внешняя регистрация закрыта (`POST /api/v1/account` и `/api/v1/auth/register` получают отказ).
9. В логах бота нет новых ERROR/WARN, `SatsPay availability changed` переходит в `up`.

Миграции ядра `m046`–`m057` необратимы. Откат — восстановить файлы бэкапа внутрь существующего тома и вернуть образ 1.5.6 с прежней командой без `--no-sync`. Бэкап тома без его пересоздания снимается до деплоя.
